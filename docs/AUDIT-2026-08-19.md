# Whole-tree audit & fix campaign — 2026-08-19

A systematic hunt for bugs, incompleteness, duplication, and "otherwise significantly
imperfect" code across the entire first-party tree (~250k lines), followed by a gated
fix campaign. This is the record of what ran, what it found, what was fixed, and what
is left for a human to decide. Companion files: `DECISION-QUEUE-2026-08.md` (the 32
open decisions), `UPSTREAM-BUGS.md` (the 78 upstream defects fixed), and
`UPSTREAM-DIVERGENCES.md` (the 10 deliberate departures).

## Method

Model-tiered orchestration. Every finding passed **sweep → dedupe/cluster →
adversarial verification (refute-by-default) → fix-in-isolated-worktree → gated
merge**. Nothing was fixed on a sweep agent's say-so; a finding had to survive an
independent verifier tasked with disproving it, and every fix shipped with a covering
test mutation-checked in *both* directions (revert → red, restore → green). The four
round-1 criticals were double-verified by two independent agents; disagreements were
adjudicated by hand against the code.

A **known-issues ledger** (836 items mined from every project doc + memory) filtered
each sweep so agents did not re-report the ~45 already-closed settings, the known
wontfixes, or prior findings. Merges were sequential, one batch per commit, with a full
build + `ctest` between each — never a batched `git add -A`.

## Coverage — four rounds, converged by coverage (not just by declining yield)

| Round | Lens | Raw findings | Verified real | Refuted |
|---|---|---|---|---|
| 1 | 47 units × 6 lenses (correctness, incompleteness, duplication, dead-reader, lifetime/LP64, parity) | 218 | ~185 | ~4% |
| 2 | 13 lenses: regression over the R1-fix diff + feature *flow* lenses crossing unit boundaries + integer/error-path/thread-safety/staleness | 84 | 78 | 4% |
| 3 | regression over the R2-fix diff + **completeness critic** + **MCCP/proxy deep-read** + ledger/doc integrity | 45 | 43 | 0% |
| 4 | **hostile-input** ("I am the malicious MUD server"), byte-level, over telnet/MCCP/ANSI/MXP/line-assembly/world-load | 5 | 5 | 0% |

The turning point was round 3. The general yield was converging (218 → 84 → 45) and it
*looked* dry — but a completeness-critic agent (tasked with "what did we never visit,
deep-read the top 3 yourself") plus a focused deep-read of the compression path found
**the campaign's worst bugs, in a surface the first three rounds had walked past**:

- **Remote DoS** — an MCCP zlib header with the FDICT bit makes `inflate` return
  `Z_NEED_DICT`, which the decompress loop neither consumed nor handled: 100% CPU spin,
  force-quit only. Server-controlled.
- **Remote heap overflow** — the `Z_STREAM_END` tail was `memcpy`'d into a 9,000-byte
  transport buffer while `avail_in` was capped only at 10,000.
- Plus an unbounded MCCP-restart `memmove`, a `strnrchr` that ignored its length bound
  (OOB read from any hostile long line), MXP argument-list leaks, and an unbounded
  telnet-subnegotiation buffer (memory-exhaustion DoS).

**Lesson recorded:** `doc_shared.cpp` (5,595 lines: the output pipeline *and* the
telnet/MCCP/ANSI decoders) was reviewed as one unit and passed twice; the
adversarial-input surface needs its own byte-level unit with an attacker's frame, and
an audit is not dry until a completeness critic has run. Round 4 was that dedicated
pass; over the now-hardened surface it found only low-severity residue — which is what
dryness earned by *coverage* looks like.

## What was fixed

168 commits (98 `fix:`), +13,911 / −2,042 across 169 files, every merge gated green,
finishing on a clean from-scratch rebuild at **73/73** `ctest` (extended on).

- **78 upstream defects** (present in the Windows source too) fixed and documented in
  `UPSTREAM-BUGS.md` — from the MCCP security cluster and the trigger/alias
  duplicate-label use-after-free down to copy-paste error messages. **10 deliberate
  divergences** recorded in `UPSTREAM-DIVERGENCES.md`.
- **Port-specific defects**: `Cmd+Q` now offers to save a modified world; `utils.directorypicker`
  actually opens a dialog instead of echoing its argument; per-document plugin
  re-entrancy guards (one world could silence another's callbacks); the notepad
  selftest's intermittent exit-abort (**root cause corrected 2026-08-19 — see *Second
  consolidation round* below.** It was the harness's own loop-free `wxYield()`
  corrupting the malloc tiny-zone free list, *not* a CoreAnimation-vs-teardown race,
  and Guard Malloc did not come up empty: it is the only tool that made the flake
  deterministic); a per-document `GetUniqueID` BSTR leak; LP64 width bugs; and dozens more.
- **~100 new covering tests** and **4 lint guards** (ASCII-literals, conflict-markers,
  doc-sections, duplicate-test-helpers). Three of those lints exist to catch mistakes
  *this campaign* made — notably the doc-numbering corruption the orchestrator's own
  merge-conflict auto-resolver introduced, which the audit's own doc-integrity stage
  caught and the new `lint_doc_sections` now prevents.

## What is deferred — and why

- **32 open decisions** → `DECISION-QUEUE-2026-08.md`. Each needs a product/design call,
  not a mechanical fix: match-Windows vs fix-toward-correctness parity choices, or a
  layer choice the code does not settle. Ten have the fix already written and await only
  the call (⚡). Two are more than cosmetic and lead the queue: **passwords can reach the
  session log** when `log_input` is on, and a **cross-window hotspot-callback
  use-after-free**.
- **Complex fixes** that need design or carry subtle interactions were deferred rather
  than forced (recorded in the round backlogs' `deferred.md`).
- **Windows-run items**: fixes to canonical source that are behaviour-preserving on
  Windows by reasoning but were not compiled there this campaign — flagged in
  `WINDOWS-VALIDATION.md` and in the relevant `UPSTREAM-BUGS` rows.

## Known coverage limitations (stated, not papered over)

The completeness critic named these; none was run this campaign, and each is a real gap:

- **No parser fuzzing.** The telnet/MCCP/ANSI/MXP/XML decoders were read adversarially
  by hand, not fuzzed. Hand review found six hostile-input bugs; a fuzzer would be a
  stronger, orthogonal check and is the recommended next step for the input surface.
- **No Windows build/run.** Everything was validated on the macOS port. The 78 upstream
  fixes and 10 divergences are type-checked but not Windows-executed; several
  `CMUSHView`/`CSendView`-resident behaviours are unreachable on the port and rest on
  code reading alone.
- **No live-MUD drive this campaign.** Behaviour was verified by the headless suite and
  in-app selftests, not by driving a real world end-to-end (a prior session did that).
- **The ledger's ~300 "open" rows** are dominated by test-coverage gaps and
  known-catalogued items, not unfixed defects; treat that count as a backlog index, not
  a defect count.

## Confidence

High on the fixed defects (each independently verified + mutation-tested + gated). The
audit is *comprehensive for the lenses run* and converged; it is **not** a proof of
absence — the coverage limitations above bound that claim honestly.

## Closing — the decision queue was worked through (2026-08-19, later the same day)

The campaign above deferred **32 items** to `DECISION-QUEUE-2026-08.md` because each
needed a product or design call rather than a mechanical fix. Those calls were taken and
the items implemented the same day, by twenty agents working in isolated worktrees. This
section records the outcome; the per-item scorecard, with the commit and the document
that records each, is the table at the top of `DECISION-QUEUE-2026-08.md`.

**29 landed and 3 are documentation-only.** (D-12, the window-geometry seam, and D-15,
multi-select file dialogs, merged after this consolidation began and are counted in the
29. This line first read "30 landed, 2 are documentation-only, and 1 was stopped" — 33
outcomes for a 32-item queue, and in any case D-29 was no longer stopped a few hours
later; both are corrected here and in the queue's own header.)

The counts in this file's own header have moved as a result: `UPSTREAM-BUGS.md` now runs
to **86** rows and `UPSTREAM-DIVERGENCES.md` to **19** sections, and `ctest` is **74/74**
with extended tests on (69/69 without). The figures quoted above describe the audit
campaign as it finished, and are left as written.

### What landed

- **Two security- or data-shaped fixes**, both of which the audit had ranked as the
  queue's leaders: a **cross-window miniwindow use-after-free** reachable from any
  plugin hotspot callback (`UPSTREAM-BUGS` 77), and **passwords reaching the session
  log** at an `IAC WILL ECHO` prompt (`UPSTREAM-BUGS` 76, fixed for the port; Windows
  needs a decision, and one residual retrospective path is still open).
- **A silent data corruption the queue did not know about.** D-10 asked why the four
  notepad line-ending conversions were inert. Answering it found that the *load* side
  was rewriting files: wxOSX does not collapse a CRLF, it expands it to two line breaks,
  so every CRLF file opened in a notepad was double-spaced on screen and saved that way.
  All 95 bundled `plugins/*.xml` are CRLF, and four separate entry points reach that
  path. That half was the priority.
- **Eleven further upstream defects** (`UPSTREAM-BUGS` 75-85) and a twelfth recorded but
  not fixed (86) — including a colour-trigger matcher that could never match an
  xterm-256 line, `WindowFilter`'s off-by-one kernel, 32-bit truncation of every SQLite
  INTEGER column in all six scripting languages, and an MXP atomic-tag veto that left
  the tag on the active list.
- **Nine deliberate divergences** recorded (`UPSTREAM-DIVERGENCES` 11-19), among them the
  bright-SGR and OSC support that had been shipping undocumented since `f06e369` — D-23
  was precisely the decision to keep it in the Windows build and write it down.
- **Two features implemented rather than retired**: a real `NSStatusItem` menu-bar item
  for *Icon Placement: System tray*, and all four of the status bar's click shortcuts.
- **Two dead-code removals** taken as deliberate upstream divergences (`DelayedSend`,
  the retired `CPrefsP2` sounds page), both unreachable on either platform since the
  2010 import.

### What the queue itself got wrong

Worth recording, because it is the same lesson the round-3 completeness critic taught
above: **a finding's context paragraph ages faster than its finding.** Six of the 32
context paragraphs were wrong at HEAD, and in two cases the error would have produced a
wrong fix:

- **D-09** asserted "Windows prompts all worlds first". It does not — stock Windows has
  the same half-closed-worlds defect the port had, so the fix is an improvement over
  upstream rather than parity with it.
- **D-13** was wrong on both of its stated exclusions, and answering it uncovered a live
  port bug it had not noticed (the connected-time pane read a different member from the
  one the reset writes, so Game ▸ Reset Connected Time already did nothing).
- **D-22**, **D-03**, **D-11** and **D-28** each misdescribed the code they cited.
- **D-29** was stopped outright: three of its load-bearing premises were false, and the
  change it asked for would have been a net loss of shipping functionality. It is closed
  with no code change and needs a fresh product call.

Two of the campaign's own recorded bug shapes recurred and were confirmed again: a test
pinning a stub's fabricated return value (`utils.menufontsize() == 0`, and
`GetScrollInfo`'s NULL-window contract, whose pinning assertion could not have failed)
and a plausible-wrong test double (`pal::CpuRaster` reporting the font em as `tmHeight`,
which under-constrains the headless parity assertions to this day).

### What remains

  indistinguishably from a mouse drag. Windows persists geometry per world; the port does
  not, and closing the gap is a feature with its own call.
- **D-04's residual** — the alias-echo path can still put a password in the scrollback,
  where a later log open retrospectively picks it up. Two candidate fixes, both
  Windows-observable, recorded with a recommendation in the queue's close-out record.
- ~~**D-29** — needs a product call on what the output-pane context menu should
  contain.~~ **Answered and implemented** (`3fe8413`, `778760d`); see *Second
  consolidation round* below.
- **D-26** — recorded as `UPSTREAM-BUGS` 86 and unverifiable from this platform.
- **No Windows build or run, still.** Ten new `WINDOWS-VALIDATION` sections
  (§4c-quintricies through §4c-quaterquadragies) say what each change needs. The
  colour-trigger matcher is the highest-risk of them: it changes the semantics of a
  comparison every colour trigger on both platforms goes through, and only a Windows run

- **The font-parity question is half-answered.** The miniwindow size pipeline is now

### Second consolidation round (2026-08-19, later still)

Twenty-two further commits landed after the consolidation above was written, twelve of
them fixes or features. A second documentation pass folded them in. What is worth
carrying forward:

**One more upstream defect, in vendored code.** `UPSTREAM-BUGS` **87**: the bundled
Lua `sqlite3` module's "does a double hold this int64 exactly?" test is `n == i64`,
which widens *both* operands, so it is vacuously true and its exact-decimal-string
branch was unreachable at all three sites. Any value a double cannot hold came back to
a script silently **rounded**. `lsqlite/lsqlite3.c` is third-party and is in
`MUSHclient.vcxproj`, so the defect ships to Windows and the fix is a local patch
upstream does not carry. With `e24ab4b` having moved the `world.Database*` readers to
the same round-trip test, the app's two SQLite surfaces now band identically — they
had been disagreeing in both directions at once.

**The notepad selftest's root cause was wrong, and the correction matters more than
the fix.** The 2026-08-18 diagnosis blamed CoreAnimation's async commit workers racing
static teardown. It was one line in `platform/notepad_selftest.cpp`: a `wxYield()`
called after `MoveNotepadWindow` so the geometry would "settle". That entry point
exits from `wxApp::OnInit`, so no event loop is active, and `wxAppConsoleBase::Yield`
then builds a **temporary** one and pumps AppKit events into a half-booted app,
corrupting the malloc tiny-zone free list. The corruption happened **mid-run**, not at
teardown, which is why three different detection sites looked unrelated to each other.
Two predictions of the old reading are false: it said every harness creating or moving
shown windows would be affected (the other five loop-free harnesses are clean, measured
under Guard Malloc), and it placed the fault at teardown. Also corrected: "invisible
under Guard Malloc" — Guard Malloc is the *only* tool that made it deterministic (6/6
with the yield, 0/6 without), where `malloc_zone_check()` at all 121 checkpoints never
fired once. Fixed by deleting the yield (`8f12c1c`); `selftest_notepad_loopfree` runs
the harness loop-free under `libgmalloc` to keep it that way, and extended mode stays
the default entry.

**Two decision-queue items were re-opened.** D-13's connected-time pane had its
*semantics* changed by owner decision (it reports the connection, not the window's
age), and D-29 — recorded above as stopped — was implemented after all, the owner
resolving the survey's blocker by asking for an integration into the existing menu
rather than a replacement of it. The queue's scorecard is authoritative and now says
so; its Close-out record is left as written.

**Nothing new went into `UPSTREAM-DIVERGENCES.md`.** Two proposals were made and both
were excluded on the file's own admission test — D-13's pane and D-29's
select-on-right-click are macOS-vs-Windows differences, not departures from upstream on
both builds — bringing that file's recorded exclusions to five. Its §17 and §18 gained
updates instead.

#### Raised in this round, deliberately not fixed

Four findings, recorded here because each needs a decision or a separate change rather
than a fix in passing:

1. **The app has two unrelated session-logging implementations, and the two menus reach
   different ones.** `CWorldChildFrame::StartLogging`
   (`platform/wx_world_child.cpp:3093`) is a raw `fopen(path, "a")` onto its own
   `m_logFile` with a hand-written `===== Log started =====` header; the output pane's
   context-menu item drives this. The **menu bar's** Connection ▸ Start/Stop Logging
   (`ID_CONN_LOG_TOGGLE`, `wx_mfc_impl.cpp:2269`) routes to the canonical
   `ID_FILE_LOGSESSION` — `CMUSHclientDoc::OnFileLogsession` → `CLogDlg`, with
   preamble/postamble, the previous-buffer dump, append-vs-truncate, and the world's
   `m_bLogOutput` / `m_log_input` / `m_bLogNotes` choices. So two identically-named
   commands **write different files in different formats**, and the world's logging
   preferences apply to only one of them. Left alone by the D-29 menu work on purpose
   (that task was a menu design; rewiring it is a behaviour change nobody asked for),
   and no duplicate canonical "Log session…" item was added, since two items with the
   same name in one menu is the outcome to avoid. **This deserves its own change.**
2. **`platform/world_frame_selftest.cpp` makes the same loop-free `wxYield()` call**
   that was fatal in the notepad harness, at `:106`, `:109` and `:154`. Measured clean
   (12/12 plain, 3/3 under Guard Malloc), so nothing was touched — but it is the same
   construct, and it is the first thing to remove if that harness ever goes flaky.
3. **The output pane's context menu labels `Find…` as `Ctrl+F`**, which wx renders as
   ⌘F on macOS, while the pane's own handler tests `RawControlDown()` — physical
   Control (`wx_outputpane.cpp:3534`). The label therefore advertises the wrong key.
   Pre-existing, and it applies to the other accelerator labels in that menu too.
4. **`m_echo_colour`'s two writers disagree.** `doc_construct.cpp` calls
   `SetDefaults(false)` — which walks `OptionsTable` writing each member from
   `iDefault` — and then, later in the same constructor, sets `m_echo_colour =
   SAMECOLOUR` (65535). `scriptingoptions_numeric.inc`'s `echo_colour` row gives a
   table default of `0`. Unlike every other double-write surveyed alongside it (see
   `336625d`, where the two writes agreed and the redundant one was deleted), **these
   two disagree**: the explicit write always wins, so the table's `0` has never taken
   effect for a fresh document on either platform, and mutating the table row alone
   would be silently invisible. Not a mechanical "make them agree" edit — `SAMECOLOUR`
   is very plausibly the correct long-standing behaviour and the table row the stale
   one, but that needs someone who knows the feature to say which is intended.
