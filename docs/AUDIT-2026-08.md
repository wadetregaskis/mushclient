# Audit, bug hunt and performance analysis — 2026-08-02

Three parallel sweeps: a test/coverage audit, a codebase-wide bug hunt, and a
performance analysis aimed at removing the output-line limit.  This file is the
durable record; what was FIXED is in the git log, what is still OPEN is below.

**Provenance and confidence.** The sweeps ran as multi-agent workflows with an
adversarial verification stage. The verification stage was cut short by an
account spend limit, so:

- Everything under "Fixed" was verified by hand against the code before the fix,
  and each carries a test.
- Everything under "Open" is **unverified**. Treat each as a lead with a
  file:line to check, not as an established defect. The first thing to do with
  any of them is confirm it still reproduces at HEAD — this project has a
  documented history of backlogs going stale because fixes land per root cause
  while findings are filed per symptom.

## What was fixed

| Commit | What |
|---|---|
| `5cb6681` | **The MFC list shim was O(N) per cursor step.** Walking any `CTypedPtrList` was O(N^2) and `RemoveHead` O(N), because iterators were mapped back to POSITIONs by scanning a side table. `m_LineList` is the scrollback and the display drain walks it per packet. Measured 5.6 ms -> 0.01 ms at the 5,000-line default; 595 ms -> 0.05 ms at 50,000. Now an intrusive list, O(1) per step. |
| `765d218` | **The display drain re-walked the buffer from the head** on every packet, every 100 ms tick and every `Note`/`Window*` call. Now walks backwards from the tail over the un-emitted lines, so cost follows new output rather than buffer size. |
| `86266c2` | **The pane rebuilt its whole wrap cache for every appended line** once at capacity — i.e. permanently — re-deriving each line's character count from its runs' bytes. Now incremental: cached char counts, absolute row numbers with a moving base. 22 ms -> 0.006 ms per 50 appends at 50,000 lines. |
| `7a37b42` | **The startup world list was session state.** The port added every world to `App.m_strWorldList` on open and save and removed it on close, destroying the user's curated set. Windows has one writer: the Global Preferences page. All seven automatic mutations removed. (Decision 1, resolved in favour of Windows semantics.) |
| `3f29d00` | Password classification read `m_bNoEcho`, which flips up to 100 ms before the masked input bar is swapped, so a password typed in that window could reach history and the log; now asks which control the text came from. The font dialog disabled effects and never seeded the caller's colour, so `utils.fontpicker` always returned black. |
| `72b5ffa` | File > New World, wxID_NEW and Quick Connect all routed to the same hook, which forced `eQuickConnect` — the canonical new-world flow (World Properties, General page) was unreachable. The command now chooses the flow, as on Windows. Verified live. |
| `9a37891` | `utils.msgbox` abort/retry/ignore and retry/cancel showed the wrong buttons and could not return the right codes; Lua `Accelerator()` never fired for any numpad key; the xterm-256 palette was all zeros under test, making six colour assertions vacuous. |

The first three are the answer to "is anything blocking unlimited scrollback" as
it stands today: the app was already paying quadratic costs at the *default*
buffer size, which is why large scrollbacks felt like a hang.

1. **Asserting only the match count.** A trigger/alias test that ends at
   `EXPECT_EQ(1L, t->nMatched)` proves the pattern matched and nothing about the
   action it was named for — the omit, the send, the log write. `nMatched` is
   incremented upstream of every action arm, so deleting the arm keeps the test
   green. This is the single most common defect in the suite.
2. **Writing the fixture with the code under test.** `CaseInsensitiveAlias`
   compiles its own caseless regexp, so the production `eIgnoreAliasCase ->
   PCRE_CASELESS` wiring is never exercised.
3. **Setup that short-circuits the path.** `OmitWithStoppedEvaluationPopsRecentLine`
   pre-sets a flag that `ProcessPreviousLine` unconditionally resets before any
   trigger runs, so the arm under test never executes.
4. **Writing a file and never reading it back.** Two log tests close and unlink
   the log without opening it.
5. **Uninitialised globals the real app initialises.** The xterm palette case;
   worth checking whether any other `InitInstance` work is missing headless.

## Decisions needed

These are the items where the right answer is a judgement call, not a fix.

### 1. `App.m_strWorldList` — RESOLVED 2026-08-02

Wade chose Windows semantics; implemented in `7a37b42`. The port no longer writes
the list at all. Kept below for the reasoning.

#### Original write-up

`platform/wx_mfc_impl.cpp` adds every world to `App.m_strWorldList` when it is
opened (`:1969`) or saved (`:2074`, `:2366`), and removes it when it is closed.
On Windows that list has exactly one writer — the Global Preferences page
(`dialogs/global_prefs/GlobalPrefs.cpp:1441`) — and it means "open these at
startup", curated by the user.

So the port has quietly repurposed a user setting as session state. The effect
is nice (your worlds come back) but it destroys the curated list, and it is
undocumented in `docs/UPSTREAM-DIVERGENCES.md`. Same shape as the `wrap_column`
bug fixed in `bec3611`: the port writing over something the user owns.

Options: keep it and record it as a divergence; keep the behaviour but move it
to a separate port-only key so the Windows setting is left alone; or drop it and
restore Windows semantics.

### 2. Default custom-colour palette on world open

`hook_open_world_file` (`:1906-1909`) overwrites the custom-colour arrays before
loading the world file, and `hook_new_world` sets every custom text slot to light
grey. Needs checking against what the canonical constructor and `SetDefaults`
already do — if they already seed these, the hooks are stomping them, and a world
whose file omits the custom colours gets the hook's values rather than the
canonical defaults.

### 3. Re-wrap on resize (carried over from the previous session)

Still open, unchanged: MUSHclient hard-wraps into the line list on both
platforms, so history has never reflowed. Making it reflow needs `hard_return`
plumbed through `SOutputLine` and is a deliberate divergence. Worth doing?

### 4. How far to take the unbounded-scrollback work

The three commits above remove the costs that bite at *today's* buffer sizes.
Going to genuinely unlimited additionally needs steps 6-8 of the plan (growable
line index, lifting the 500,000 cap, int64 scroll geometry), and steps 9-12 are
what make a million-line buffer pleasant rather than merely possible. Steps 9
and 12 are large and touch the `IWorldView` wire format. How far should this go?

## printf format attributes — the remaining 65 warnings

`MC_PRINTF_FORMAT` (guarded: real on GCC/clang, nothing on MSVC) is now on
TFormat, CFormat, CString::Format, CMUSHclientDoc::Trace, ThrowErrorException and
CErrorException.  It found seven real bugs, fixed in `73f30e7`.

65 width-mismatch warnings remain.  **They are deliberately not "fixed" yet**,
because the obvious fix is wrong:

    strMsg.Format ("%ld lines", someInt);     // warns on macOS

On macOS `long` is 64-bit, so `%ld` against an `int` is a mismatch.  On the
32-bit Windows build this project also targets, `long` and `int` are BOTH 32-bit
and the existing specifier is correct.  Changing `%ld` to `%d` would silence
macOS and introduce the mismatch on Windows.

The correct shape is to cast the ARGUMENT and leave the specifier alone:

    strMsg.Format ("%ld lines", (long) someInt);

which is right on both.  That makes it a mechanical sweep of 65 sites in
Windows-shared code — worth doing deliberately, in its own commit, not folded
into a bug fix.

Severity: low.  On AArch64 and x86-64 every integral vararg occupies an 8-byte
slot with the value extended, so `%ld` against an `int` reads the right value.
The one direction that can actually be wrong is `%d` against a `long` (24 of the
65), which truncates above 2^31 — reachable only by a line or byte count past two
billion, which is exactly the territory the unbounded-scrollback work opens up.
